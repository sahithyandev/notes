## Verification

The process of checking whether the software conforms to its specification. Asks: are we building the product right?

## Validation

The process of checking whether the software does what the user actually requires. Asks: are we building the right product?

Both static and dynamic techniques are used in the V&V process:

- Static V&V  
  Inspections. Software examined without execution.
- Dynamic V&V  
  Testing. Software executed with test inputs and behaviour observed.

## V&V Confidence

Aim of V&V is to establish confidence that the system is _fit for purpose_.

Depends on:

- Software purpose  
  The level of confidence depends on how critical the software is to an organisation.
- User expectations  
  Users may have low expectations of certain kinds of software.
- Marketing environment  
  Getting a product to market early may be more important than finding defects in the program.

## Stages of Testing

- Development testing  
  Individual components tested independently.
- System testing  
  Entire system tested; emergent properties checked.
- Acceptance testing  
  Testing with customer data; confirms system meets user needs.
