MCUs operate on discrete binary values. The physical world produces continuously varying voltages. Signal conversion hardware bridges this gap.

An ADC samples an analog voltage and maps it to a binary integer.

$$
D = \left\lfloor \frac{V_\text{in}}{V_\text{ref}} \times (2^n - 1) \right\rfloor
$$

Here:

- $D$: digital output value
- $V_\text{in}$: input voltage
- $V_\text{ref}$: reference voltage (maps to maximum digital value)
- $n$: Resolution in bits. Determines precision of conversion.

An $n$-bit ADC produces $2^n$ discrete levels.

Key parameters:

- Sampling rate  
  Maximum conversions per second.
- Reference voltage  
  Upper bound of the measurable input range.

Needed because sensors (temperature, pressure, light, sound) produce analog voltages that a digital MCU cannot read directly.

## Types

Classified by how conversion is performed:

- Parallel conversion  
  All bits are determined simultaneously in a single step. Fast. Hardware cost scales exponentially with resolution.
- Serial conversion  
  Bits are resolved 1 at a time (or approximated iteratively) over multiple clock cycles. Lower hardware cost. Slower.

### Flash ADC

Uses $2^n - 1$ comparators in parallel, each with a different reference voltage from a resistor ladder. All comparators fire simultaneously. A priority encoder converts the thermometer code to binary.

- Fastest possible conversion: 1 clock cycle
- Hardware cost grows exponentially with bit depth
- Used in oscilloscopes and high-speed RF sampling where speed is critical

### Counter-Ramp ADC

A counter starts at 0 and increments each clock cycle. Its value feeds an internal DAC (typically an R-2R ladder), generating a staircase voltage that rises 1 step per clock. A comparator checks the staircase against $V_{in}$ on every cycle. When the staircase exceeds $V_{in}$, the comparator trips and the counter value is latched as the digital output.

$$
T_{conv} = D \times T_{clk}
$$

Here:

- $D$: digital output value (number of steps to reach $V_{in}$)
- $T_{clk}$: clock period

Conversion time varies with $V_{in}$. A near-zero input converts in 1 cycle. Full-scale requires up to $2^n - 1$ cycles.

- Simplest serial ADC design: 1 comparator, 1 counter, 1 DAC
- Slower than SAR for most inputs. Used in low-cost, low-speed applications.

### Tracking ADC

A variant of the counter-ramp ADC. Replaces the reset counter with an up/down counter that continuously follows $V_{in}$.

On each clock cycle:

- Counter increments by 1 if the DAC output is below $V_{in}$
- Counter decrements by 1 if the DAC output is above $V_{in}$

The counter never resets. The output is always the current counter value, which tracks the input in real time.

- No start-conversion trigger needed
- Fast for slowly changing inputs: only steps by ±1 per cycle to stay locked
- Slow for large step changes: must slew ±1 per cycle from the current value to the new level, taking up to $2^n$ cycles in the worst case
- Unsuitable for multiplexed inputs that switch between unrelated voltages

### Successive Approximation Register ADC

Uses 1 comparator, 1 internal DAC, and an $n$-bit SAR register. Resolves the output 1 bit per clock cycle via binary search, from MSB to LSB.

Conversion sequence for each bit $k$ (starting at $k = n-1$):

1. Set bit $k$ of the SAR register to 1.
2. Feed the SAR value into the internal DAC to produce a trial voltage.
3. Compare the DAC output to $V_{in}$.
4. If $V_{in} \geq V_{DAC}$: keep bit $k$ at 1. If $V_{in} < V_{DAC}$: clear bit $k$ to 0.
5. Move to bit $k-1$ and repeat.

After $n$ cycles the SAR register holds the final digital output.

- Takes exactly $n$ clock cycles regardless of $V_{in}$
- Low hardware cost: 1 comparator, 1 DAC, 1 shift register
- Most common ADC type in MCUs (ATmega, STM32, ESP32 all use SAR ADCs)

### Dual-Slope ADC

2-phase operation:

1. Integrate $V_{in}$ for a fixed time period $T_1$, charging a capacitor.
2. Discharge the capacitor with a fixed reference voltage $-V_{ref}$; measure the time $T_2$ to reach zero.

$$
V_{in} = V_{ref} \times \frac{T_2}{T_1}
$$

The result depends only on the ratio of times, not on component tolerances. Noise averages out over the integration period.

- Very high accuracy and noise rejection
- Slow (conversion takes milliseconds)
- Used in digital multimeters and precision instrumentation

### Sigma-Delta ADC

Oversamples the input at a rate far above the [Nyquist rate](/s3/data-communication-and-networking/signals#nyquist-theorem), then applies noise shaping and a digital decimation filter to produce a high-resolution output. Resolution up to 24 bits.

Slow conversion rate (latency proportional to oversampling ratio).

Used in audio codecs and precision sensors (load cells, pressure). Not covered in this module.

### Comparison

| ADC Type                 | Resolution (bits) | Speed       | Cost   |
| ------------------------ | ----------------- | ----------- | ------ |
| Flash                    | 4–12              | Very fast   | High   |
| Successive Approximation | 8–16              | Medium–fast | Low    |
| Dual-Slope               | 12–18             | Slow        | Medium |
| Sigma-Delta              | 12–24             | Slow        | Low    |

## Implementation in MCUs

MCUs expose multiple analog input pins but contain only 1 ADC circuit internally. An analog multiplexer (MUX) sits between the input pins and the ADC, connecting exactly 1 pin to the ADC at a time.

```
Analog pins
  A0 ─┐
  A1 ─┤
  A2 ─┼─── MUX ─── Sample & Hold ─── ADC ─── Digital output
  A3 ─┤
  A4 ─┘
```

The MUX channel is selected in software before triggering a conversion. Only 1 channel converts at a time; all others are disconnected from the ADC during that cycle.

A sample-and-hold circuit captures the selected pin's voltage the moment conversion begins. The held voltage stays constant for the full conversion duration, preventing errors from a changing input signal mid-conversion.

The reason for sharing 1 ADC across all channels is silicon area. An ADC contains a comparator, an internal DAC, control logic, and reference circuitry — a large transistor count. Duplicating this per pin would multiply silicon cost proportionally. A multiplexer adds only a few transistors per channel.

<Note>

Because channels are sampled sequentially, 2 analog readings taken in different conversion cycles are not simultaneous. Applications requiring phase-accurate multi-channel sampling need an external simultaneous-sampling ADC.

</Note>
