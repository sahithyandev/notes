Layer 4 of the OSI model. Operates in end stations only; not in network nodes. Primary interface to the network for application developers.

Provides end-to-end data delivery between end stations. Shields upper layers from network peculiarities. Improves on network layer services (e.g. adds reliability).

## Functions

- Handle network layer peculiarities: fragmentation, multiplexing, inverse multiplexing.
- Specify type of service.
- Establish and delete connections.
- Flow control.

### Multiplexing and Demultiplexing

Transport layer manages multiple connections on a single host using $16$-bit port numbers to distinguish services.

- Outgoing connections: **multiplexing**.
- Incoming connections: **demultiplexing**.

### Segmentation

Applications may send large amounts of data. Transport layer breaks them into smaller _segments_ and adds transport layer headers. The segments are sent individually and reassembled at destination.

Segmentation is done to work with Maximum Transmission Unit (MTU) limitation.

### Connection Establishment

Normal flow: client sends connection request; server accepts.

Problems on unreliable networks:

- Lost packets.
- Delayed packets.
- Duplicate packets.

Sequence numbers detect and reject duplicates.

Scenarios:

- **(a) Normal** — CR sent, ACK returned, data transfer begins.
- **(b) Stale CR** — old duplicate CR arrives; server ACKs; client sends REJECT because sequence number is unrecognised.
- **(c) Duplicate CR + duplicate ACK** — both CR and ACK are duplicated; client rejects the stale ACK via REJECT.

### Connection Termination

Requirements:

- Both sides must agree the connection is closed.
- No data loss.
- No indefinite waiting.

**Three-way handshake** — standard release mechanism.

Scenarios:

- **(a) Normal** — Host 1 sends DR; Host 2 sends DR + ACK; Host 1 releases and ACKs; Host 2 releases.
- **(b) Final ACK lost** — Host 2 times out and releases anyway.
- **(c) Response lost** — Host 1 retransmits DR; eventually receives response; releases.
- **(d) Response and subsequent DRs lost** — repeated timeouts; both sides release after $N$ timeouts.

## Service Types

- **Connection-oriented** — connection established before data transfer.
- **Connectionless** — no prior connection; data sent directly.
- **Reliable** — guaranteed delivery and ordering.
- **Unreliable** — no delivery guarantee.
- **Multicast** — one-to-many delivery.

## Service Primitives

- Listen  
  Wait for an incoming connection.
- Connect  
  Establish a connection.
- Send  
  Transmit data.
- Receive  
  Wait for incoming data.
- Disconnect  
  Release connection.

## Addressing

### TSAP

Aka. Transport Service Access Point. Transport layer address. Each host may contain one or more TSAPs.

$$
\text{TSAP} = \text{host address} + \text{port number}
$$

### Port

16-bit numeric component of a TSAP. Distinguishes multiple connections on one host.

Port identification methods:

- Pre-arrangement (e.g., specified in a URL).
- Well-known ports  
  Such as 25 for SMTP and 80 for HTTP. First 1024 port numbers are assigned to well-known services by IANA.
- Portmapper — maps service names to port numbers.
- Application-defined.

### Client-Server Model

**Server** — listens on a fixed port; waits for client connections.

**Client** — initiates a connection (or sends a datagram) to the server's port.

On connection, server hands off to the responsible service process.

## Flow Control and Buffering

Sender transmits as fast as possible without causing data loss.

- Sender retains copies of sent-but-unacknowledged data.
- Sender may transmit up to the receiver's current buffer space without loss.
- Sending beyond buffer space risks dropped data.
