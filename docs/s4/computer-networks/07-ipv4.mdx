## Datagram

The basic unit of data transferred in the network layer.

```
 0               1               2               3
 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|Version|  IHL  |    DSCP/ToS   |          Total Length         |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|         Identification        |Flags|     Fragment Offset     |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|      TTL      |   Protocol    |        Header Checksum        |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                       Source IP Address                       |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                    Destination IP Address                     |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                       Options (variable)                      |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
```

Header fields:

- Version (4 bits)  
  IP version. Set to `4` for IPv4.
- IHL — Internet Header Length (4 bits)  
  Header size in 32-bit words. Minimum `5` = 20 bytes.
- DSCP/ToS (8 bits)  
  Quality of service classification.
- Total Length (16 bits)  
  Full packet size in bytes, header included. Maximum $65{,}535$ bytes.
- Identification (16 bits)  
  Groups fragments belonging to the same original datagram.
- Flags (3 bits)  
  Reserved, Don't Fragment (DF), More Fragments (MF).
- Fragment Offset (13 bits)  
  Position of this fragment within the original datagram, in 8-byte units.
- TTL (8 bits)  
  Decremented by each router. Packet dropped when it reaches $0$.
- Protocol (8 bits)  
  Transport-layer protocol: `6` = TCP, `17` = UDP.
- Header Checksum (16 bits)  
  Error detection for the header only. Recomputed at each hop.
- Source IP Address (32 bits)  
  Sender's IP address.
- Destination IP Address (32 bits)  
  Receiver's IP address.
- Options (0–40 bytes)  
  Present only if IHL > 5. Rarely used in practice.

Payload carries the transport-layer segment (TCP or UDP).

## Network and Host Parts

An IP address is divided into network and host portions.

- Network part  
  Identifies the network.
- Host part  
  Identifies the device within the network.

Hosts with the same network part belong to the same network and can communicate without a router.

### Network Size

Depends on the number of bits allocated to the host portion. More host bits means a larger network.

## IP Address Allocation

- Host assignment  
  Manually configured, or dynamically via DHCP.
- Network assignment  
  ISP allocates an address block. ISP gets blocks from a RIR (e.g. APNIC). RIR gets blocks from ICANN.

## Dynamic Host Configuration Protocol

Aka. DHCP. Dynamically assigns IP addresses to hosts. Allows automatic configuration, address reuse, and host mobility.

Uses the DORA exchange:

- Discover  
  Client broadcasts to locate available DHCP servers.
- Offer  
  Server responds with an available IP address and lease terms.
- Request  
  Client broadcasts a request for the offered address.
- Ack  
  Server confirms the lease; client configures the address.

## Packet Forwarding

Moving a packet toward its destination hop by hop.

- Same network: direct delivery.
- Different network: forward to the next-hop router.

Routers use forwarding tables keyed on destination network. The datagram is unchanged except for mutable fields (e.g. TTL, checksum).

## Address Resolution Protocol

Aka. ARP. Maps IP addresses to MAC addresses within a local network. Works by broadcasting a query; the target host replies with its MAC address.

Cannot operate beyond the local network because it relies on broadcast.

## Longest Prefix Match

Aka. LPM. When forwarding a packet, a router selects the most specific (longest) matching prefix in its routing table.

- Software implementation: tree search, slow but space-efficient.
- Hardware implementation: TCAM, fast but expensive and power-hungry.

## Hop-by-Hop Fragmentation

In IPv4, any router can fragment a packet that exceeds a link's MTU. Reassembly happens only at the destination. Adds processing overhead at each hop.

## Issues

- Restricted address space  
  32-bit addresses limit the pool to ~4.3 billion. Exhausted by growth of connected devices.
- Huge routing tables  
  Flat addressing caused global BGP tables to exceed 1 million entries. Stored in TCAM, which is expensive, power-hungry, and physically limited.
- Slow LPM  
  Longest prefix match over large tables is costly even with TCAM.
- Convergence delays  
  Topology changes take longer to propagate when routing tables are large.
