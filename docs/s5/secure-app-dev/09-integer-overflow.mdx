Integer overflow is not itself a [memory safety](/s5/secure-app-dev/memory-safety) violation. It leads to one when the overflowed value is used:

- For pointer arithmetic
- As a `malloc` argument
- As an array index

An overflowed value used this way often leads to a buffer overflow, or directly to an out-of-bounds read or write.

## Number Representation

Unsigned integer  
An $n$-bit unsigned integer $x = (x_{n-1}, \dots, x_0)$ is stored in binary.

$$
x = \sum_{i=0}^{n-1} 2^i x_i
$$

Signed integer  
Stored in two's complement. The most significant bit has a negative weight.

$$
x = -2^{n-1} x_{n-1} + \sum_{i=0}^{n-2} 2^i x_i
$$

The range is $-2^{n-1} \leq x < 2^{n-1}$. Negation is $-x = 2^n - x$.

Floating point  
A single-precision IEEE 754 float uses 32 bits.

- Sign  
  1 bit, $x_{31}$.
- Exponent  
  8 bits, $x_{30}$ to $x_{23}$, stored with bias $127$.
- Fraction  
  23 bits, $x_{22}$ to $x_0$.

$$
x = (-1)^{x_{31}} \cdot \left(1 + \sum_{i=1}^{23} x_{23-i} 2^{-i}\right) \cdot 2^{[x_{30}:x_{23}] - 127}
$$

It encodes values up to about $3.4 \times 10^{38}$, all integers with at most 6 decimal digits, and all values $2^n$ for $-126 \leq n \leq 127$.

Examples:

- $3.3125$  
  Binary $11.0101_2 = 1.10101_2 \times 2^1$. Sign bit is $0$. Exponent is $1 + 127 = 128 = 10000000_2$. Fraction is $10101$ padded with zeros. Result is `01000000010101000000000000000000`.

<Note>

Reinterpreting the bits of a float as an integer allows arithmetic tricks. Quake III Arena's fast inverse square root computes $\frac{1}{\sqrt{x}}$ with `i = 0x5f3759df - (i >> 1)` on the float's bit pattern, followed by a Newton iteration. It ran about 4 times faster than other algorithms.

</Note>

## Unsigned Overflow

An $n$-bit unsigned integer represents $x$ with $0 \leq x < 2^n$. On overflow, C++11 requires the value be reduced modulo $2^n$, so unsigned arithmetic never triggers undefined behaviour.

An $n$-bit unsigned integer can overflow in multiple cases, for $0 \leq a,b < 2^n$:

- Addition  
  $a+b \geq 2^n$
- Subtraction  
  $a-b < 0$ if $b > a$
- Multiplication  
  $a \cdot b \geq 2^n$

Examples:

- Stagefright  
  `uint8_t *buffer = malloc(size + chunk_size)` overflows if `size + chunk_size` exceeds the unsigned range, allocating a buffer smaller than intended. Fixed by checking `size > UINT_MAX - chunk_size` before adding, rejecting the allocation instead of letting the sum wrap.

## Signed Overflow

By the C++11 standard, if evaluating an expression produces a result not mathematically defined or not representable by its type, the behaviour is undefined. This applies only to signed integers.

An $n$-bit signed integer can overflow in multiple cases, for $-2^{n-1} \leq a,b < 2^{n-1}$:

- Addition or subtraction  
  $a+b \geq 2^{n-1}$ or $a+b < -2^{n-1}$.
- Negation  
  $a = -2^{n-1} \implies -a = 2^{n-1}$, an asymmetry of two's complement since $2^{n-1}$ is not representable.
- Multiplication  
  $a \cdot b \geq 2^{n-1}$ or $a \cdot b < -2^{n-1}$. Multiplication by $-1$ reduces to negation.
- Division  
  $\frac{-2^{n-1}}{-1} = 2^{n-1}$, reducing to negation.

Examples:

- Java's `binarySearch` computed `mid = (low + high) / 2`. For large arrays, `low + high` overflows a signed 32-bit int before the division, producing a negative or invalid index. Fixed by computing `mid = low + (high - low) / 2` instead, since `high - low` stays within the array's valid index range and cannot overflow.

## Type Conversion

C automatically converts between types, known as coercion, performed by the compiler and capable of unintended consequences.

- `float` to `int`  
  Truncates the fractional part.
- `double` to `float`  
  Rounds to the nearest representable value.

Converting a smaller type to a larger one uses:

- Sign extension  
  High bits set to the sign bit, used when the source is signed.
- Zero extension  
  High bits set to `0`, used when the source is unsigned.

For an arithmetic operation between 2 operands, the compiler chooses a common type:

- Same type, same rank  
  No conversion.
- Same type, different rank  
  Convert the smaller type to the larger.
- Unsigned operand with rank at least the signed operand's rank  
  Convert both to unsigned.
- Signed type can represent every value of the unsigned type  
  Convert both to signed.
- None of the above  
  Convert both to unsigned, using the signed operand's type as the unsigned width.

<Note>

An integer type's rank increases in this order, lowest to highest:

- `_Bool`
- `char`, `signed char`, `unsigned char`
- `short`, `unsigned short`
- `int`, `unsigned int`
- `long`, `unsigned long`
- `long long`, `unsigned long long`

A signed type and its unsigned counterpart of the same width have equal rank.

</Note>

## Fixing Integer Overflow

Checking `width * height > UINT_MAX` after computing `width * height` is unsound, since the multiplication has already overflowed by the time the check runs.

A correct check divides instead of multiplying, guarding against division by $0$:

```c
void* new_8bit_image(unsigned int width, unsigned int height)
{
  if (!width || (UINT_MAX / width < height)) return NULL;
  unsigned int memory = width * height;
  void* data = malloc(memory);
  return data;
}
```

GCC and clang also provide built-in overflow-checking arithmetic, e.g. `__builtin_umul_overflow`, `__builtin_add_overflow`, `__builtin_sub_overflow`, for various integer types.

```c
unsigned int memory;
if (__builtin_umul_overflow(width, height, &memory)) {
  return NULL;
}
void* data = malloc(memory);
```
