The simplex algorithm is an iterative method that moves between vertices of the feasible region, improving the objective at each step, until no adjacent vertex gives further improvement.

## Standard Form

Before applying simplex, convert the LP to standard form.

- Objective  
  Maximization (negate a minimization objective).
- Constraints  
  All equalities, obtained by adding slack, surplus, or artificial variables.
- Variables  
  All non-negative.

<Note>

$\le$ constraints get a slack variable added. $\ge$ constraints get a surplus variable subtracted and an artificial variable added. $=$ constraints get an artificial variable added.

</Note>

## Basic Feasible Solution

For a standard form LP with $m$ constraints and $n$ variables, a basic solution sets $n - m$ variables to 0 (the non-basic variables) and solves the constraints for the remaining $m$ (the basic variables).

A basic feasible solution is a basic solution with all variables $\ge 0$.

Basic feasible solutions correspond to vertices of the feasible region. Each simplex iteration exchanges 1 basic variable for 1 non-basic variable, moving to an adjacent vertex.

## Iteration Steps

Each simplex iteration operates on a tableau representing the current vertex.

<Note title="Proof Hint">

- Check optimality: if all objective row coefficients are $\ge 0$, stop
- Choose entering variable: most negative coefficient in the objective row
- Choose leaving variable: minimum ratio test, smallest $\frac{b_i}{a_{ij}}$ over rows with $a_{ij} > 0$ in the entering column
- Pivot: divide the pivot row by the pivot element, then eliminate the entering variable from all other rows
- Repeat

</Note>

- Unbounded solution  
  Occurs when the entering column has no positive entry, so no ratio test can be formed.
- Degenerate pivot  
  Occurs when a basic variable equals 0, giving a minimum ratio of 0, so the objective does not improve on that iteration. A tie in the ratio test produces a degenerate basic variable in the next tableau.

<Note>

Repeated degenerate pivots can cycle through the same set of bases indefinitely. Bland's rule, choosing the lowest-indexed eligible entering and leaving variables, prevents cycling.

</Note>

## All Slack Starting Method

Used when every constraint is $\le$ with $b_i \ge 0$, so the origin is a feasible starting vertex.

- Add a slack variable to each constraint.
- Use the slack variables as the initial basic feasible solution.
- Run the iteration steps directly.

## Big M Method

Used when constraints are mixed ($\ge$ or $=$ present), so the origin is not feasible and artificial variables are needed.

<Note title="Proof Hint">

- Add artificial variables to $\ge$ and $=$ constraints
- Penalize each artificial variable by $-M$ in the objective (maximization), for a large $M$
- Run the iteration steps until optimal
- Check the value of every artificial variable at optimality

</Note>

- Feasible  
  All artificial variables equal 0 at optimality, so the solution is feasible for the original problem.
- Infeasible  
  Any artificial variable is positive at optimality, so the original problem has no feasible solution.

<Note>

$M$ is treated symbolically, larger than any finite number, so its coefficient must remain more negative than any other coefficient throughout the iterations.

</Note>

## Two Phase Method

Used as an alternative to Big M when a symbolic large constant is undesirable.

<Note title="Proof Hint">

- Phase 1: minimize the sum of artificial variables, ignoring the original objective
- If the phase 1 minimum is 0, the artificial variables leave the basis and a feasible vertex for the original problem is found
- Drop the artificial variables and restore the original objective
- Phase 2: run the iteration steps on the original objective from this starting vertex

</Note>

- Phase 1 minimum $> 0$  
  The original problem is infeasible, stop.
- Phase 1 minimum $= 0$  
  Proceed to phase 2 with the feasible vertex found.

## Dual Simplex Algorithm

Starts from a dual-feasible but primal-infeasible solution and iterates toward primal feasibility. Dual feasibility is defined by the [dual](/s5/operational-research/linear-programming#duality) of the LP.

Used when a tableau is optimal but has a negative right-hand side, for example after adding a new constraint to an already-solved LP.

<Note title="Proof Hint">

- Check feasibility: if all $b_i \ge 0$, stop, the solution is primal feasible
- Choose leaving variable: most negative $b_i$
- Choose entering variable: minimum ratio $\frac{c_j}{a_{ij}}$ over columns with $a_{ij} < 0$ in the leaving row
- Pivot on that element
- Repeat

</Note>

<Note>

Dual simplex avoids re-solving the LP from scratch after a constraint is added, since the existing optimal tableau is already dual feasible.

</Note>
