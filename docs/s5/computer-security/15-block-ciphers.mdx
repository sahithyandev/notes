A block cipher operates on a fixed-length block of plaintext $m$ of $n$ bits, mapping it to a ciphertext block $c$ of the same length under a secret key $k$, both drawn from $\{0,1\}^n$.

Large messages are divided into blocks and encrypted independently per block.

$$
c_i \leftarrow e_k(m_i), \quad m_i \leftarrow d_k(c_i)
$$

For a fixed key $k$, the encryption function $e_k$ is a bijection on $\{0,1\}^n$, so it is invertible via $d_k$. Per [Kerckhoffs's principle](/s5/computer-security/kerckhoffs-principle), $e$ and $d$ are public. Only $k$ is secret.

A block cipher's key design objective is to behave like a family of pseudorandom permutations (PRP) indexed by $k$.

A block cipher encrypts a set of bits or characters at a time, whereas a stream cipher encrypts a single bit or character at a time.

## Iterated Block Cipher Design

### Round Design

An iterated block cipher builds $e_k$ by applying a simple keyed transformation, the round function, to the block $r$ times in succession.

- Round  
  One application of the round function. A single round is weak; security comes from repetition, and increasing $r$ raises security up to a stable level.
- Round key $k_i$  
  The key used in round $i$, derived from $k$ by the key schedule.
- Key schedule  
  The algorithm that expands $k$ into the round keys $k_1,...,k_r$.

Examples:

- DES: 16 rounds, Feistel structure, 48-bit round keys from a 56-bit key.
- AES: 10, 12, or 14 rounds for 128, 192, or 256-bit keys, SP-network structure.
- Triple DES: DES run three times with two or three independent keys.

### Feistel Cipher

Named after Horst Feistel. Splits the plaintext block into halves $(L_0, R_0)$ and iterates a round function $F$, keyed by $k_i$, over $r$ rounds, swapping the final halves to produce the ciphertext.

Each encryption round:

$$
L_i \leftarrow R_{i-1}, \quad R_i \leftarrow L_{i-1} \oplus F(k_i, R_{i-1})
$$

Each decryption round, using the round keys in reverse order:

$$
R_{i-1} \leftarrow L_i, \quad L_{i-1} \leftarrow R_i \oplus F(k_i, L_i)
$$

The round operation is invertible independent of $F$, so the same hardware or software can perform both encryption and decryption by reversing the order of round keys.

Design parameters of a Feistel cipher:

- Block length $n$.
- Number of rounds $r$.
- Definition of the round function $F$.
- Key schedule generating each round key $k_i$ from $k$.
- Length of the secret key $k$.

### SP-Network

Proposed by Claude Shannon in 1945: a series of linked permutation and substitution operations. AES, the successor to DES, is based on this design, rather than the Feistel structure. Its round operations are visualized in the [interactive guide to AES](https://sahithyan.dev/post/interactive-guide-to-aes).

- Diffusion  
  Permutations disperse the statistical characteristics of each input bit among all output bits.
- Confusion  
  Substitutions create a complex relationship between the input and key with the output, providing the cipher's non-linearity.

## Modes of Operation

A mode of operation is a recommended standard for using a block cipher to build a scheme for arbitrary-length messages. Plaintext $m$ is divided into blocks $m_1,...,m_n$ of the length the underlying cipher specifies, padding the last block if needed.

DES was standardized with 4 modes: ECB, CBC, OFB, CFB. CTR was added later to allow parallel encryption of data blocks.

- ECB, for short secrets such as session keys.
- CBC, for bulk data encryption.
- OFB, for real-time streamed content.
- CFB, for streamed content.
- CTR, for data that must be encrypted or decrypted in parallel.

### ECB Mode

Electronic Code Book, the simplest mode: each block is encrypted independently.

$$
c_i \leftarrow e_k(m_i), \quad m_i \leftarrow d_k(c_i)
$$

Vulnerabilities:

- Information leakage  
  Identical plaintext blocks ($m_i = m_j$) produce identical ciphertext blocks ($c_i = c_j$), letting an attacker spot repetition.
- Block deletion  
  Blocks are independent, so an attacker can delete blocks in transit and the receiver cannot detect the modification.
- Block splicing  
  For the same reason, an attacker can copy blocks from one message into another undetected.

Error propagation: a single bit error in a received ciphertext block corrupts the entire corresponding plaintext block on decryption. There is no propagation into other blocks.

### CBC Mode

Cipher Block Chaining fixes ECB by chaining ciphertext into each block's encryption, giving every block context from its neighbors.

$$
c_1 \leftarrow e_k(m_1 \oplus IV), \quad c_i \leftarrow e_k(m_i \oplus c_{i-1}) \text{ for } i > 1
$$

$$
m_1 \leftarrow d_k(c_1) \oplus IV, \quad m_i \leftarrow d_k(c_i) \oplus c_{i-1} \text{ for } i > 1
$$

The IV can be a fixed public value (e.g. all-zero), which need not be transmitted, or a random nonce, which must be transmitted with the ciphertext as $IV, c_1,...,c_n$.

Error propagation: a single bit error in a received ciphertext block corrupts the entire corresponding plaintext block, plus a single bit in the next block. This is one-block error propagation.

### OFB Mode

Output Feedback lets a block cipher operate as a stream cipher: it generates a keystream $Y_i$ of $b$ bits at a time, XORed with the plaintext or ciphertext stream.

$$
Y_i \leftarrow e_k(Y_{i-1}), \quad c_i \leftarrow m_i \oplus Y_i, \quad m_i \leftarrow c_i \oplus Y_i
$$

$Y_0 \leftarrow IV$. Both encryption and decryption use only the encryption operation $e_k$.

The keystream can be precomputed before any ciphertext arrives, so OFB suits real-time streamed content.

Error propagation: a single bit error in a received ciphertext block corrupts only the corresponding single bit of plaintext. There is no propagation into other blocks.

### CFB Mode

Cipher Feedback also lets a block cipher operate as a stream cipher, similar to OFB, but feeds the ciphertext itself back into the keystream generator.

$$
Z_i \leftarrow e_k(Y_{i-1}), \quad c_i \leftarrow m_i \oplus Z_i^*, \quad Y_i \leftarrow Y_{i-1} \ll c_i
$$

$Y_0 \leftarrow IV$, and $Z_i^*$ is the $b$ most-significant bits of $Z_i$. Decryption mirrors this, also using only $e_k$.

Unlike OFB, the keystream depends on the ciphertext and cannot be precomputed before ciphertext arrives, making CFB less useful than OFB for real-time streaming.

Error propagation: a single bit error in a received ciphertext block corrupts a single bit in the corresponding plaintext block, then keeps corrupting the input buffer $Y_i$ until it is flushed after $n/b$ rounds, completely corrupting $n/b - 1$ further blocks. This causes severe error propagation.

### CTR Mode

Counter mode is similar to ECB but removes its disadvantages while keeping its advantage of parallel processing.

$$
c_i \leftarrow m_i \oplus e_k(IV \oplus \langle i \rangle_b), \quad m_i \leftarrow c_i \oplus e_k(IV \oplus \langle i \rangle_b)
$$

$\langle i \rangle_b$ is the binary representation of $i$ as a $b$-bit number.

Each plaintext block is encrypted independently, like ECB, so blocks can be processed in parallel. The counter also gives each block context, so unlike ECB, an attacker cannot cut-and-paste or rearrange ciphertext blocks undetected.

Vulnerability: the counter input $IV + i$ must never be reused for a subsequent encryption under the same key $k$.
