<Aka>LFSR</Aka>. Builds a [keystream](/s5/computer-security/stream-ciphers) from
a register of $n$ bits $s_0, s_1, \ldots, s_{n - 1}$, where each new bit is the
XOR of a fixed subset of the current bits.

In an LFSR, the register is a row of $n$ 1-bit memory cells. Its contents are the current $n$-bit state. Each clock tick outputs 1 designated bit, shifts every cell's bit to the next cell, then inserts the feedback bit into the vacant cell.

$$
s_i = c_1 s_{i-1} \oplus c_2 s_{i-2} \oplus \cdots \oplus c_n s_{i-n}, \quad i \ge n
$$

<Symbols>
  <Sym s="c_1, \ldots, c_n \in \{0, 1\}">
    the feedback taps, fixed for a given LFSR.
  </Sym>
  <Sym s="s_0, \ldots, s_{n-1}">
    the initial state, acting as the secret key or seed.
  </Sym>
</Symbols>

## Connection Polynomial

<Aka>feedback polynomial</Aka>. The taps are written as a connection polynomial
over $\mathrm{GF}(2)$.

<Note>

$\mathrm{GF}(2)$ is the field $\{0, 1\}$. Addition is XOR and multiplication is bitwise AND, so each coefficient is either 0 or 1.

</Note>

$$
p(x) = 1 + c_1 x + c_2 x^2 + \cdots + c_n x^n
$$

Each term $c_k x^k$ marks whether the tap $k$ steps back feeds into the recurrence, so $p(x)$ is a complete description of the LFSR's wiring, independent of the initial state.

### Primitive Polynomial

A degree-$n$ polynomial $p(x)$ over $\mathrm{GF}(2)$ is primitive **iff** it is irreducible and any root has multiplicative order $2^n - 1$ in $\mathrm{GF}(2^n)$. Its successive powers therefore generate every nonzero field element.

To test whether a degree-$n$ polynomial $p(x)$ is primitive, first check that it is irreducible over $\mathrm{GF}(2)$. Let $M = 2^n - 1$. For every prime factor $q$ of $M$, compute $x^{M/q} \bmod p(x)$. The polynomial is primitive **iff** none of these remainders equals 1.

The output sequence has period $2^n - 1$, the maximum possible for an $n$-bit register, **iff** $p(x)$ is a primitive polynomial over $\mathrm{GF}(2)$.

A non-primitive connection polynomial still produces a periodic sequence, just with a period shorter than $2^n - 1$, and possibly a period that depends on the initial state.

## Key Space

With a fixed public connection polynomial, the initial $n$-bit state is the key. The all-zero state is excluded because it remains zero forever. The key space therefore has $2^n - 1$ members.

## Characteristic Polynomial

The recurrence itself corresponds to a characteristic polynomial, related to the connection polynomial by $x^n$ reversal.

$$
p^*(x) = x^n p(1/x) = x^n + c_1 x^{n-1} + c_2 x^{n-2} + \cdots + c_n
$$

$p^*(x)$ is primitive over $\mathrm{GF}(2)$ **iff** $p(x)$ is. Either polynomial can be used to check for maximal period. Its roots in the extension field $\mathrm{GF}(2^n)$ determine the solutions of the recurrence and therefore the possible output sequences.

## Combining LFSRs

An LFSR alone fails the unpredictability requirement of a secure keystream generator, since its recurrence is linear. Practical generators instead combine several LFSRs of different lengths and connection polynomials through a nonlinear Boolean function $f$.

$$
k_i = f\left(s_i^{(1)}, s_i^{(2)}, \ldots, s_i^{(m)}\right)
$$

<Symbols>
  <Sym s="s_i^{(j)}">the output bit of the $j$-th LFSR at step $i$.</Sym>
  <Sym s="f">a fixed nonlinear function of the $m$ component outputs.</Sym>
</Symbols>

## Clock Control

Component LFSRs need not advance together. A clock-control function can select which registers advance at each step from their current output bits. Irregular clocking disrupts the fixed alignment between component sequences and the output keystream.

Clock control must not leave a component's output statistically detectable in the resulting keystream.

## Security

A combining or clock-control function must satisfy several properties for the resulting keystream to resist analysis.

- Balance  
  $f$ outputs 0 and 1 equally often across all input combinations, so the keystream carries no statistical bias.
- High nonlinear order  
  $f$ cannot be approximated by a linear or affine function of its inputs, since a close linear approximation reduces the combiner to a single large LFSR.
- Correlation immunity  
  $k_i$ is statistically independent of each individual $s_i^{(j)}$, so no component LFSR's output correlates with the combiner's output.

A higher correlation immunity order generally forces a lower achievable nonlinear order, so the 2 properties trade off against each other rather than maximising independently.

## Attacking

### Berlekamp-Massey Algorithm

Targets a single LFSR directly, exploiting the linearity of its recurrence.

- $2n$ consecutive output bits give $n$ linear equations in the $n$ unknown taps $c_1, \ldots, c_n$.
- Solving this system (the Berlekamp-Massey algorithm does so in $O(n^2)$) recovers every tap and the state at that point.
- The attacker then computes every following output bit from the recurrence.

### Correlation Attack

Targets a combined generator whose combining function $f$ correlates with 1 of its component LFSRs.

- The attacker guesses the connection polynomial of the correlated LFSR (public in most designs) and searches over its $2^n - 1$ possible initial states.
- Each candidate state produces a candidate output sequence, compared against the keystream bit by bit.
- The candidate whose sequence agrees with the keystream noticeably more than $50\%$ of the time is accepted as the recovered state.

This reduces recovering an $m$-LFSR generator's full state from 1 search of size $2^{\sum n_j} - 1$ to $m$ separate searches of size $2^{n_j} - 1$ each, so correlation immunity directly defends against it.

If clock control repeatedly holds 1 component's output while another advances, the output can retain detectable structure from the held component. Statistical tests can then reveal its period or state.
