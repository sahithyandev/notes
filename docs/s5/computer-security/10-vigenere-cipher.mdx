A [classical](/s5/computer-security/ciphers#classical-cipher) and [poly-alphabetic](/s5/computer-security/ciphers#poly-alphabetic-cipher) cipher. Invented in 1533 by Giovan Battista Bellaso, misattributed to Blaise de Vigenère.

Each letter is shifted by an amount that depends on its position in the message, so the ciphertext letter frequencies are flattened. Also a stream cipher.

You can find an implementation of the Vigenère cipher in [sahithyandev/ciphers](https://github.com/sahithyandev/ciphers/blob/main/src/vigenere-cipher.c).

## Encryption

The key is repeated and aligned with the plaintext (as shown below for the key `LEMON`).

```
plaintext:  ATTACKATDAWN
key:        LEMONLEMONLE
```

Each plaintext letter is shifted forward in the alphabet by the position of the key letter above it (A = 0, B = 1, ..., Z = 25).

- `A` shifted by `L` (11) gives `L`
- `T` shifted by `E` (4) gives `X`

For a key of length $n$, each key letter picks one of 26 possible shift amounts, independently of the other $n - 1$ key letters. So the number of possible keys is $26 \times 26 \times \dots$ ($n$ times) $= 26^n$.

## Decryption

The key is repeated and aligned with the ciphertext the same way. Each ciphertext letter is shifted backward by the position of the key letter above it.

- `L` shifted back by `L` (11) gives `A`
- `X` shifted back by `E` (4) gives `T`

## Attacking

Security depends significantly on keeping the key length secret. Once the key length is found, the cipher can be attacked in the same manner as a shift cipher, using statistical properties of the plaintext language for each block of ciphertext extracted from separate keyword positions.

### Kasiski Test

The Kasiski test determines the keyword length.

Steps:

- Locate a repeating character sequence in the ciphertext.
- Count the distances between successive occurrences of that sequence.
- Take the greatest common divisor of these distances as the keyword length, or a multiple of it.

Repeated short strings, often common bigrams or trigrams of the language, that align to the same keyword position produce the same ciphertext string.

## Worked Example

Plaintext `wearediscoveredsaveyourself` under keyword `DECEPTIVE`, with $A = 0$ to $Z = 25$.

The keyword is repeated to match the plaintext length.

```
plaintext:   w e a r e d i s c o v e r e d s a v e y o u r s e l f
keystream:   D E C E P T I V E D E C E P T I V E D E C E P T I V E
ciphertext:  Z I C V T W Q N G R Z G V T W A V Z H C Q Y G L M G J
```

Each position adds the keystream letter modulo $26$.

- $w (22) + D (3) = 25 = Z$
- $s (18) + V (21) = 39 \equiv 13 = N$

Ciphertext is `ZICVTWQNGRZGVTWAVZHCQYGLMGJ`.

Decryption subtracts the keystream letter modulo $26$ at each position.

- $Z (25) - D (3) = 22 = w$
- $N (13) - V (21) = -8 \equiv 18 = s$

Numbering ciphertext positions from 1, the trigram `VTW` appears at positions 4 to 6 and 13 to 15.

Distance between the occurrences is $13 - 4 = 9$. Only 1 distance is available, so the keyword length is a divisor of $9$. Divisors are $1$, $3$, $9$. Lengths $1$ and $3$ are ruled out by trying them and getting non-language output. Keyword length is $9$.

Split the ciphertext into 9 columns, column $i$ holding positions $i, i + 9, i + 18, \dots$. Each column is a shift cipher under one keyword letter.

Frequency analysis on each column recovers the shifts $3, 4, 2, 4, 15, 19, 8, 21, 4$, which is the keyword `DECEPTIVE`.

Decrypting with `DECEPTIVE` gives `wearediscoveredsaveyourself`.

<Note>

Each column here holds only 3 letters, too few for reliable frequency analysis. A real attack needs many multiples of the keyword length.

</Note>
