A byte-oriented [keystream generator](/s5/computer-security/stream-ciphers) built around a permutation $S$ of the 256 byte values $S[0], \ldots, S[255]$, rather than an LFSR. Designed by Ron Rivest in 1987.

$$
S: \{0, \ldots, 255\} \to \{0, \ldots, 255\}
$$

Generating the keystream has 2 phases: the Key Scheduling Algorithm builds an initial permutation from the key, and the Pseudo-Random Generation Algorithm repeatedly mutates it to emit 1 output byte per step.

## Key Space

For a fixed key length of $l$ bytes, RC4 accepts $256^l = 2^{8l}$ input keys. RC4 permits $1$ to $256$ bytes, so its full input key space has $\sum_{l=1}^{256} 256^l$ members. The key scheduling algorithm maps these inputs into at most $256!$ internal permutations, so distinct input keys can produce the same state.

## Key Scheduling Algorithm

Initialises $S$ to the identity permutation, then scrambles it using the secret key $K$ (1 to 256 bytes), reused cyclically if shorter than 256 bytes.

$$
\begin{aligned}
&S[i] = i, \quad i = 0, \ldots, 255 \\
&j = 0 \\
&\text{for } i = 0 \text{ to } 255: \\
&\quad j = (j + S[i] + K[i \bmod \text{len}(K)]) \bmod 256 \\
&\quad \text{swap } S[i] \text{ and } S[j]
\end{aligned}
$$

  <Sym s="j">

</Symbols>

After 256 swaps, every byte value has moved to a key-dependent position, and $S$ passes unchanged into the PRGA.

## Pseudo-Random Generation Algorithm

Produces the keystream 1 byte at a time, advancing $S$ further at every step.

$$
\begin{aligned}
&i = 0, \quad j = 0 \\
&\text{repeat:} \\
&\quad i = (i + 1) \bmod 256 \\
&\quad j = (j + S[i]) \bmod 256 \\
&\quad \text{swap } S[i] \text{ and } S[j] \\
&\quad k = S[(S[i] + S[j]) \bmod 256]
\end{aligned}
$$

$k$ is the output byte, XORed with the corresponding plaintext byte exactly as in any other stream cipher.

Each output byte depends on the entire current permutation rather than a fixed linear recurrence, so RC4 has none of the structure LFSR-based generators rely on, at the cost of a much larger internal state ($256!$ possible permutations) than the key itself.

## Security Analysis

RC4 was used in SSL/TLS, WEP, and WPA. It is now broken or deprecated in each protocol.

- Early-byte bias  
  The 2nd keystream byte is $0$ with probability close to $2/256$. A uniform byte has probability $1/256$. The early output is distinguishable from random.
- Related-key weakness  
  WEP prefixes the long-term key with a public 24-bit IV. Certain IVs make the first KSA swaps expose 1 key byte through the first PRGA byte. The Fluhrer-Mantin-Shamir attack collects enough such packets to recover the long-term key.
- Keystream bias  
  Later PRGA output also has statistical biases. Mantin's ABSAB bias can reveal a plaintext sent under many unrelated keys. The attack uses byte frequencies across sessions. It does not recover a key.

Discarding the first 256 or more bytes removes some early-output biases. Keeping a public IV separate from the key prevents the WEP-style related-key attack. Neither change makes RC4 safe for new systems. Modern protocols use authenticated ciphers such as AES-GCM or ChaCha20-Poly1305.
