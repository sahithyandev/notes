Models plaintext as a bit stream, combined with a random keystream via a reversible operation, bitwise XOR.

$$
c_i = m_i \oplus k_i, \quad m_i = c_i \oplus k_i
$$

Both encryption and decryption must generate the identical keystream $k_i$.

- No error propagation  
  A bit error in a transmitted ciphertext bit corrupts only the corresponding decrypted plaintext bit.
- Efficient for real-time data (audio, video streaming) when the keystream generation algorithm is fast.

## Stream Encryption Scheme

A stream cipher is already a complete [encryption scheme](/s5/computer-security/ciphers). It needs no mode of operation.

- Arbitrary length  
  The keystream is generated to any length and XORed with the plaintext bit by bit. No padding, and ciphertext length equals plaintext length.
- Randomisation  
  The keystream generator takes an [initialization vector](/s5/computer-security/ciphers) alongside the key, so the same plaintext under the same key gives different ciphertext for different IVs.

## Keystream Generator

A function that generates a stream of pseudorandom bits $k_0, k_1, k_2, \dots$ from a short secret key. Used in practical stream ciphers.

A secure keystream generator must satisfy:

- Long period  
  The period $N$ of the repetition of the sequence, where $k_i = k_{i+N}$, must be large for all $i$.
- Pseudo-randomness  
  The sequence must pass statistical random number tests.
- Unpredictability  
  Computationally infeasible to determine the full keystream from any part of it, of any length.

## Malleability

An encryption scheme is malleable **iff** an attacker can transform a ciphertext of an unknown message $m$ into a ciphertext of a related message $f(m)$, without knowing $m$ or the key.

The XOR-combiner stream cipher is malleable. Given $c = m \oplus k$, the attacker chooses a mask $\Delta$ and sends $c' = c \oplus \Delta$.

$$
c' \oplus k = (m \oplus k \oplus \Delta) \oplus k = m \oplus \Delta
$$

The plaintext changes by exactly $\Delta$, an attacker-chosen relation, with no other change. Flipping bit $i$ of $c$ flips bit $i$ of the plaintext.

Malleability here follows from 2 properties together, not from the keystream being random or pseudorandom.

- The combiner is XOR, which is linear and known to the attacker.
- No integrity check covers the ciphertext.

Removing either property breaks the attack. A self-synchronising stream cipher feeds past ciphertext bits into the keystream, so a flipped bit garbles a run of following plaintext instead of one clean bit.

A scheme is non-malleable **iff** any tampering with the ciphertext makes it decrypt to a value unrelated to $m$, or makes decryption reject.

## Breaking the Cipher

Reusing a keystream $k$ across 2 messages $m_1$ and $m_2$ produces ciphertexts $c_1 = m_1 \oplus k$ and $c_2 = m_2 \oplus k$.

$$
c_1 \oplus c_2 = (m_1 \oplus k) \oplus (m_2 \oplus k) = m_1 \oplus m_2
$$

The keystream cancels. An attacker holding $c_1$ and $c_2$ recovers $m_1 \oplus m_2$ without $k$. Plaintext redundancy separates it into $m_1$ and $m_2$. Knowing one plaintext gives the other directly.

Knowing one plaintext also recovers the keystream, $k = c_1 \oplus m_1$. Any further message under the same $k$ can then be forged. The attacker picks $m'$ and sends $c' = m' \oplus k$, which decrypts to $m'$, an existential forgery.

## Examples

### One-Time Pad

To encrypt a message $m$ (of length $n$), a keystream $k$ (of length $n$) is generated that is random and never reused. The message bits are XORed with the keystream bits to produce the ciphertext.

Impractical as it requires a key as long as the message and never reused, but applications need a short key and reuse it across many messages.

### Ron's Cipher (RC4)

RC4, designed by Ron Rivest in 1987, is a byte-oriented keystream generator built around a permutation $S$ of the 256 byte values $S[0], \ldots, S[255]$, rather than an [LFSR](/s5/computer-security/linear-feedback-shift-registers).

- Key Scheduling Algorithm (KSA)  
  Initialises $S$ to the identity permutation, then scrambles it by repeatedly swapping entries, using the secret key (1 to 256 bytes, reused cyclically) to bias each swap.
- Pseudo-Random Generation Algorithm (PRGA)  
  Produces 1 keystream byte per step: 2 indices into $S$ are advanced and their entries swapped, then the byte at the sum of the 2 swapped entries (mod 256) is output.

Each output byte depends on the entire current permutation rather than a fixed linear recurrence, so RC4 has none of the structure the LFSR-based generators above rely on, at the cost of a much larger internal state ($256!$ possible permutations) than the key itself.

RC4 was widely deployed in SSL/TLS, WEP, and WPA for its speed and simplicity, but is now considered broken. The first output bytes are measurably biased toward certain values, letting an attacker who sees the same key reused across enough sessions recover plaintext without ever recovering the key, and RC4 has since been deprecated in the protocols that used it.
