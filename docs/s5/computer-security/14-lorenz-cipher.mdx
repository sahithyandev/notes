A [classical](/s5/computer-security/ciphers#classical-ciphers), [poly-alphabetic](/s5/computer-security/ciphers#poly-alphabetic-ciphers), [stream](/s5/computer-security/ciphers#stream-ciphers) cipher. Encrypts a Baudot-coded plaintext bit stream into 5 ciphertext bit streams. Each bit is masked by a fresh keystream bit, so ciphertext symbol frequencies are flattened.

Implemented by the Lorenz machine, an electromechanical inline cipher attachment built by C. Lorenz AG for the German Army high command in World War 2. It sat between a teleprinter and the transmission line, enciphering each character as it was typed and deciphering at the far end. The Allies called the machine and its traffic Tunny.

### Baudot Code

A fixed-width (5 bits) character encoding, invented by Émile Baudot in 1870 for printing telegraphs.

Fixed width is the key property. The receiver slices the bit stream every 5 bits to find character boundaries, unlike the variable-length symbols of Morse code. This is why the Lorenz machine treats plaintext as a clean stream of 5-bit units.

A 5-bit code spans only $2^5 = 32$ symbols, too few for letters, digits, punctuation, and control codes. 2 of the 32 codes are mode switches rather than characters.

- Letters shift  
  Following codes are read as letters.
- Figures shift  
  Following codes are read as digits and symbols.

The machine holds the current mode. The same 5-bit pattern means different characters in the 2 modes, so the effective alphabet is about 60 symbols.

## Encryption

Each 5-bit Baudot code is XOR-ed with a 5-bit random sequence, generated by 12 shift registers in 3 groups:

- 5 $\chi$ registers, lengths 41, 31, 29, 26, 23.
- 5 $\psi$ registers, lengths 43, 47, 51, 53, 59.
- 2 $\mu$ registers, lengths 61, 37.

At each clock tick $t$:

- $K = (\chi_i \oplus \psi_i)$ for $i = 1, \dots, 5$.
- $t \leftarrow t + 1$, and the $\chi$ registers advance.
- $\mu^{(1)}$ advances every tick, and conditionally triggers $\mu^{(2)}$ to advance.
- $\mu^{(2)}$ conditionally triggers the $\psi$ registers to advance.
- Output $K$.

Key space:

$$
2^{41+31+29+26+23+43+47+51+53+59+61+37} = 2^{501}
$$

<Note>

Register settings can be rotated on different schedules to behave like session keys, e.g. $\mu$ registers changed daily, $\chi$ registers monthly, $\psi$ registers quarterly.

</Note>

## Decryption

The receiver starts the 12 registers from the shared settings and runs the same clocking, producing the identical keystream $K$. XOR is its own inverse, so XOR-ing each 5-bit ciphertext code with $K$ returns the plaintext code.

## Attacking

The keystream is fully determined once the register settings are fixed, so 2 messages sent in depth, under the same settings, break the cipher.

- XOR the 2 ciphertexts. The keystream cancels, leaving $P_1 \oplus P_2$, the XOR of the 2 plaintexts.
- Slide known language fragments against $P_1 \oplus P_2$ to separate the 2 plaintexts, then XOR either plaintext with its ciphertext to recover the keystream.
- The $\psi$ registers stall on many ticks, so the keystream carries $\chi$ structure. Statistical tests on the ciphertext bits expose the $\chi$ register lengths and starting positions without a depth.

## Worked Example

One Baudot character `A`, code $11000$, with keystream bits $01101$ for this tick.

Encryption XORs the code with the keystream bit by bit.

$$
11000 \oplus 01101 = 10101
$$

Ciphertext code is $10101$.

Decryption XORs the ciphertext with the same keystream bits.

$$
10101 \oplus 01101 = 11000
$$

Recovered code is $11000$, the character `A`.

For the attack, a second message encrypts code $00110$ at this tick under the same settings, giving ciphertext $00110 \oplus 01101 = 01011$.

$$
10101 \oplus 01011 = 11110 = 11000 \oplus 00110
$$

The keystream $01101$ has cancelled, leaving the XOR of the 2 plaintext codes.
