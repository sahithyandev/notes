A digital signature scheme is a triple of algorithms over a key pair $(PK, SK)$, where $SK$ is the private signing key held only by the signer and $PK$ is the public verification key.

- Key generation  
  Produces $(PK, SK)$. $PK$ is published, often in a certificate; $SK$ is kept secret.
- $\text{Sign}(SK, m)$  
  Outputs a signature $s$ computed from the message $m$ and $SK$. In practice $H(m)$ (a [hash function](/s5/computer-security/hash-functions) $H$) is used instead of $m$. The digest is fixed size, so signing cost stays constant for any length, and it avoids mathematical structure exploits that come from signing large raw data blocks directly.
- $\text{Verify}(PK, m, s)$  
  Deterministic check that returns accept only if $s$ matches $m$ under $PK$.

The signature is a mathematical function of both $m$ and $SK$. Changing either input changes the valid signature.

## Properties

- Authentication  
  A valid $s$ proves the message came from the holder of $SK$.
- Integrity  
  Any change to $m$ after signing makes $\text{Verify}$ reject.
- Non-repudiation  
  $s$ is bound uniquely to $SK$, which is known only to the signer, so no one else could have produced it. The signer cannot later deny signing $m$.

## Forgery

The signing oracle is the honest signer seen as a black box: they submit a chosen message $m_i$ and receive $s_i = \text{Sign}(SK, m_i)$, without learning $SK$.

An adaptive chosen-message attack lets them query the oracle on messages of their choice, each query picked after seeing earlier answers.

- Existential forgery  
  They output one valid pair $(m', s')$ where $m'$ was never queried to the oracle. The message need not be meaningful.
- Selective forgery  
  They forge a signature on a target message fixed in advance.
- Universal forgery  
  They can sign any message, equivalent to recovering $SK$.

A scheme is secure when existential forgery under an adaptive chosen-message attack is infeasible.

## RSA Digital Signature

Uses the same key pair as [RSA](/s5/computer-security/rsa) encryption, with the roles of $e$ and $d$ reversed. Here $n$ is the RSA modulus, $d$ the private exponent, $e$ the public exponent, and $H$ a hash function.

The two modes differ in whether the message is put through RSA directly or only its hash is, and in what gets transmitted.

- With message recovery  
  The message itself is signed: $\sigma = m^d \bmod n$. Only $\sigma$ is sent, and $m$ is recovered during verification. Requires $m < n$, so it fits only short messages.
- Without message recovery  
  Only the digest is signed: $\sigma = H(M)^d \bmod n$. The pair $(M, \sigma)$ is sent, so $M$ travels in the clear. Works for any message length. This is the form used in practice.

### Verification

- With recovery  
  Compute $m' = \sigma^e \bmod n$ using the signer's public key, and check it matches the expected message.
- Without recovery  
  Compute $h' = H(M')$ and $h = \sigma^e \bmod n$, accept **iff** $h = h'$.

Signing cost is a hash plus a single exponentiation with a full-length exponent $d$. Verification cost is a hash plus a single exponentiation with the small exponent $e$, plus a comparison.

<Note>

RSA signing is not literally RSA decryption applied to plaintext. In practice, the message is encoded per the PKCS#1 standard before signing, rather than used directly.

</Note>

## Paper vs Digital

- Paper signature  
  A static mark tied to the physical medium. The same mark is used regardless of the document text, so it does not depend on the content.
- Paper verification  
  Subjective visual comparison against a reference, or forensic handwriting analysis by an expert.
- Digital signature  
  A value derived from the message content and $SK$, so it differs for every message.
- Digital verification  
  Deterministic checking of $\text{Verify}(PK, m, s)$, with trust in $PK$ established through a Public Key Infrastructure and its certificate trust chains.
